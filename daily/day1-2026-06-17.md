## 二、关键踩坑记录

### 坑 1：`dev:spa` 无法测试本地 Builtin Agent

**现象**：Agent 初始化走 tRPC 请求 → 生产服务器 → 生产服务器的 `@lobechat/builtin-agents` 不含我们的 `interviewer` slug → 返回 null。

**解决**：切换到全栈本地开发（`bun run dev`），需要 Docker 运行完整依赖链。

**理解要点**（面试可讲）：
- `dev:spa` 是纯前端代理模式，仅适合 UI 开发
- Builtin Agent 的 `systemRole` 在**服务端**运行时生成（`getAgentRuntimeConfig` → `runtime(ctx).systemRole`）
- 新增 Builtin Agent 必须本地服务端才能验证

### 坑 2：docker-compose 缺少 `.env` 文件

**现象**：`bun run dev:docker` 报错 `env file .../.env not found`。

**解决**：在 `docker-compose/dev/` 下创建 `.env`，变量名必须匹配 `docker-compose.yml` 中的 `${VAR}` 插值。

**注意**：变量名和项目根 `.env` 不完全一致（如 `RUSTFS_ACCESS_KEY` vs `S3_ACCESS_KEY_ID`），需要看 `docker-compose.yml` 确认。

## 四、面试考点沉淀

### 考点 1：Monorepo 的包分层设计
```
packages/builtin-agents    → Agent 定义（业务配置层）
packages/agent-runtime      → Agent 运行时引擎（底层，不可改）
packages/app-config         → Feature Flag 等全局配置
src/features                → UI 组件（表示层）
apps/server                 → tRPC API（服务层）
```

### 考点 2：Feature Flag vs 编译时 Tree Shaking
- Feature Flag：**运行时**动态开关，适用于需要服务端控制的开关
- Tree Shaking：**编译时**静态移除，死代码永远不会打包
- LobeHub 的实践：`FEATURE_FLAGS` 环境变量 → 服务端下发 → Zustand store → 组件按条件渲染

### 考点 3：Builtin Agent 初始化链路
```
前端 useInitBuiltinAgent('interviewer')
  → agentService.getBuiltinAgent(slug)
    → tRPC lambdaClient.agent.getBuiltinAgent.query({ slug })
      → 服务端 AgentService.getBuiltinAgent(slug)
        → AgentModel.getBuiltinAgent(slug)
          → 查 DB 是否存在
          → 不存在则调 getAgentPersistConfig(slug) 获取配置
          → 插入 DB 并返回 AgentItem
```

### 考点 4：DeepSeek Prompt 设计注意事项
- ChatML format 兼容 OpenAI API
- System Prompt 控制在 800 tokens 以内，DeepSeek 对冗长 system msg 敏感
- 结构化输出（JSON/Markdown 表格）需要在 Prompt 中给出明确格式样本
