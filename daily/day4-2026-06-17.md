## 二、设计决策

### 拖拽分隔条实现

使用 `useRef` + `useEffect` 注册全局 `mousemove/mouseup` 事件，避免 React state 频繁更新导致卡顿。拖拽时只更新 ref（不触发渲染），`mouseup` 时更新 state。实际上这里用 state 更新宽度，因为需要驱动 `style` 变化。但全局监听器在组件挂载时注册一次即可。

### 不创建独立 ChatPanel

右面板直接 render `{children}`（即 `<Conversation />`），不额外封装。LobeHub 的 Conversation 组件已经包含完整的聊天逻辑（消息列表、输入框、流式渲染），封装反而增加耦合。

## 五、面试考点

### 考点 9：拖拽分隔条实现模式

- 用 `useRef` 标记拖拽状态，避免每次 mousemove 触发 React 渲染
- 全局事件监听用 `useEffect` + cleanup 管理生命周期
- 初始宽度 / 最小宽度 / 最大比例三约束确保布局不会坍塌

### 考点 10：条件布局模式

```ts
// 不是 if/else 两个完全不同的 DOM，而是同一套组件用不同容器包裹
{isInterview ? (
  <InterviewChat><Conversation /></InterviewChat>  // 有左侧面板
) : (
  <Flexbox><Conversation /></Flexbox>              // 标准全宽
)}
```

好处：Conversation 组件零改动，所有聊天逻辑保持不变。
