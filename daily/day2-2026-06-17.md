### 1.4 内存问题诊断与修复

**现象**：next-server 进程内存占用 9.54GB，系统 swap 11.55GB

**根因三条**：

| # | 根因 | 详细 |
|---|---|---|
| 1 | Turbopack × 89 package monorepo | 4 个 worker × ~416MB，追踪 ~10,000+ TS 文件。HMR 编译缓存只增不减（内存泄漏） |
| 2 | Vite + Next.js 双编译 | `devStartupSequence.mts` 同时跑 Vite (9876) + Next.js (3010)，各自维护完整模块依赖图 |
| 3 | 16GB 物理内存不足 | Docker 5 容器 + VS Code + Chrome 多标签页，总需求量 > 16GB |

**修复措施**：

| 措施 | 文件 | 说明 |
|---|---|---|
| `dev:next` 加内存限制 | `package.json` | `NODE_OPTIONS=--max-old-space-size=4096`，限制 Node heap |
| `dev:docker:light` 新增 | `package.json` | 仅启动 PostgreSQL + Redis，跳过 RustFS + SearXNG（省 ~220MB） |

**日常开发策略**：

```
改 UI 组件      → bun run dev:spa           (纯 Vite, ~500MB)
改 Agent/后端    → bun run dev:next          (仅 Next.js + 内存限制)
需要全栈验证     → bun run dev               (完整环境, 但每 2-3h 重启一次)
Docker 依赖      → bun run dev:docker:light  (仅 PG + Redis)
```

## 三、面试考点沉淀

### 考点 5：Builtin Agent 的生命周期

```
定义期（编译时）:
  BuiltinAgentDefinition { slug, persist, runtime }
  → 注册到 BUILTIN_AGENTS Record
  → types.ts 添加 slug 枚举

初始化期（运行时）:
  useInitBuiltinAgent(slug) 
  → tRPC → 服务端 AgentModel.getBuiltinAgent(slug)
  → 查 DB，不存在则用 getAgentPersistConfig(slug) 创建
  → 返回 AgentItem → 存入 Zustand agentMap + builtinAgentIdMap

对话期（每次消息）:
  resolveAgentConfig(agentId) → 读 agentMap 获取 slug
  → getAgentRuntimeConfig(slug, ctx) → 调用 runtime 函数
  → createSystemRole(userLocale) → 生成 System Prompt
  → 拼装到 LLM 请求
```

### 考点 6：Turbopack 在 monorepo 中的内存问题

- Turbopack 是 Rust 增量编译器，但 JS/TS 模块依赖图巨大时仍需大量内存
- 每个 worker 持有完整模块图副本，N 个 worker = N 倍内存
- `NODE_OPTIONS=--max-old-space-size=4096` 限制 V8 heap 上限
- 开发时分离前端/后端独立启动是 monorepo 项目的标准实践（`nx`、`turbo` 等工具的核心价值）

### 1.5 内存优化第二轮（深水区）

**背景**：第一轮优化后 next-server 仍达 4.77GB，VS Code 8GB+，Docker 3.98GB

| 措施 | 文件 | 说明 |
|---|---|---|
| Docker 容器内存硬限制 | `docker-compose/dev/docker-compose.yml` | postgresql `mem_limit: 512m`，redis `mem_limit: 128m` |
| Docker Desktop VM 建议 | 手动操作 | Settings → Resources → Memory → 1.5GB |
| VS Code tsserver 内存上限 | `.vscode/settings.json` | `typescript.tsserver.maxTsServerMemory: 2048`；files.watcherExclude 排除 .next/node_modules/dist |
| Webpack 备用模式 | `package.json` | `dev:next:webpack` — `--no-turbo`，内存 ~1.5GB |
| 完整内存优化手册 | `daily/memory-optimization-guide.md` | 包含 Docker/VS Code/Next.js/Chrome 四维度优化 |

**最终开发策略**：

```
┌──────────────────────────────────────────────────────┐
│ 改 UI 组件/样式/页面     → dev:spa (Vite ~500MB)      │
│ 改 Agent Prompt/服务端   → dev:next (需本地 server)    │
│ 长时间运行后端            → dev:next:webpack (稳定1.5G)│
│ Docker                  → dev:docker:light (PG+Redis) │
│ 紧急释放内存             → pkill next; pkill vite;     │
│                           sudo purge                  │
└──────────────────────────────────────────────────────┘
```

### 1.7 `dev:spa` vs `dev:next` 核心区分

| | dev:spa (Vite) | dev:next (Next.js) |
|---|---|---|
| 前端代码 | ✅ 本地 | ✅ 本地 |
| API / Agent | ❌ 走生产服 `app.lobehub.com` | ✅ 本地 server |
| System Prompt | ❌ 生产服的 Prompt | ✅ 你的 interviewer Prompt |
| 适用场景 | 写 UI、调样式 | 测 Agent、对话联调 |
| 内存 | ~500MB | ~4GB (Turbopack) |
